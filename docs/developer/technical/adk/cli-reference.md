# CLI reference

**Status:** GA
**Version checked:** 2026-10-28
**Technical owner:** Unassigned
**Last reviewed:** 2026-11-16


Run `npx kassis-addon <command>` after installing `@kassis/addon-cli`, or `node tools/adk/kassis-addon.mjs <command>` from this repository. The packed CLI is a bundle. `npx kassis-adk-mcp` starts the MCP server from the same package. Help and errors name the command `kassis-addon`. `--help` exits 0. `--version` prints the CLI version and exits 0. `--flag value` and `--flag=value` both work. `--json` on every command prints `{ "ok", "issues", "data" }`. An issue is `{ "code", "severity", "message", "fix", "file", "line" }`. An unknown command prints usage and exits 1. Exit 0 is success. The MCP server also exposes offline discovery tools (`list_facades`, `get_facade`, `list_extension_points`, `list_events`, `get_event_schema`, `get_tier_matrix`, `search_docs`, `get_example`, `find_core_feature`) that read packaged kit data with no network.

| Command              | Flags                                                         | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `init`               | `--id` `--dir` `--publisher` `--tier` `--rung`                | Copies `templates/kassis-addon`. `--id` is required. Publisher defaults to `kassis`, tier to 2, rung to 1. Tier 1 is refused unless the publisher is `kassis`. Any other publisher gets an id prefix of `<publisher>-` when the id does not already start with it. Rung 1 is server only. Rung 2 adds UI. Rung 3 adds UI and migrations.                                                                                                                                                                                                                                                                                                                             |
| `build`              | `--only=server` or `--only=ui`                                | Writes `dist/server/index.js`. Also writes `frontend/dist/index.js` when `src/ui/index.ts` exists. Prints each path. Exits 1 when `initialize` is missing, or when the UI was built and `register` is missing.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `check`              | `--json`                                                      | Validates `manifest.json` against manifest v2. Schema errors use the existing KADK-1xx codes. A permission outside `<id>.` is KADK-110. Also refuses a banned dependency (KADK-221) and a private approval, notification, audit, user, or role table (KADK-310). An explained `REUSE.md` row warns with KADK-311. An owned table with no `database.tableNotes` warns with KADK-312. Writes `.kassis/evidence/reuse-core.json`. When `process.packs[]` is set, checks each `process/*.json` offline: namespace (KADK-125), missing file (KADK-126), key or kind mismatch (KADK-127), undeclared permission (KADK-128), undeclared record type (KADK-129), unresolved reference (KADK-314), envelope (KADK-316), duplicate key (KADK-317), unlisted file (KADK-318). A kind with no host schema warns KADK-313 and does not check `body`. For manifest v2, a missing record access check is KADK-729, a `return true` or throw-only access check is KADK-730, a missing deletion handler on owned tables is KADK-731, and an empty or throw-only deletion handler is KADK-732. The record-type scaffold fails this until those handlers are filled in. Writes `.kassis/evidence/mandatory-contract.json`. |
| `conformance`        | `--json`                                                      | Runs the addon-testkit import check on `src/`, `frontend/`, and built `dist/server/index.js` and `frontend/dist/index.js` when those files exist. Also rejects an up script with no down script.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `test`               | `--json`                                                      | Runs `node --test` in `./test`. Prints `No test directory` and exits 0 when that folder is missing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `dev`                | `--image` `--json`                                            | Starts a local container with Docker or Podman. The image is `--image`, then `KASSIS_DEVHOST_IMAGE`, then `~/.kassis/devhost.json`, then `ghcr.io/kassis-ai/kassis-devhost:latest`. It pulls that image when it is not local. The addon directory is mounted read-only at `/opt/kassis/dev-addon` and the port is published on 127.0.0.1. It also starts a tier 2 runner container on an internal network and does not mount a Docker socket. It does not build an image.                                                                                                                                                                                                                                                                                                |
| `migrate`            | `up` `down` `status` `--target` `--json`                      | Runs only against the database of the dev host started by `dev`. If that host is not running, it refuses. `--target` is refused unless it is that same database.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `doctor`             | `--requirements` `--json`                                     | Checks that Node is 20 or newer, that `npm whoami` succeeds for `https://npm.pkg.github.com` (the token is not printed), that a key file exists under `~/.kassis/keys`, that `KASSIS_ADK_INSTANCE` answers `GET /api/v1/adk/version`, and that `manifest.hostApi` accepts `HOST_API_VERSION`. With `--requirements`, scans `src/`, `frontend/`, `test/`, and built `dist/server/index.js` for `ctx` facade calls refused at the manifest tier (`tier-matrix.json`); issues use KADK-219.                                                                                                                                                                                                                                                                                                                                                                        |
| `requirements`       | `--json`                                                      | Parses Must rows in `REQUIREMENTS.md` and requires each `FR-*` / `NFR-*` id to appear in a file under `test/` or in `GAPS.md`. Writes `.kassis/evidence/requirements-coverage.json`. Untraced Must ids use KADK-719; a missing `REQUIREMENTS.md` uses KADK-718. `certify` runs the same gate before the attestation check.                                                                                                                                                                                                                                                                                                                                          |
| `plan`               | `--json`                                                      | Reads every `FR-*` and `NFR-*` row in `REQUIREMENTS.md` and requires a rung in `PLAN.md`: `configuration`, `extension-point`, `facade`, `own-code`, or `gap`. Writes `.kassis/evidence/requirement-mapping.json` with counts per rung. A missing `PLAN.md` is KADK-720, an unmapped id is KADK-721, and a bad or duplicate rung is KADK-722. `certify` runs the same gate.                                                                                                                                                                                                                                                                                       |
| `budgets`            | `--json`                                                      | Soft thin-addon budgets: owned tables, `routes.mount` calls, production dependencies, and server source bytes. Over a limit needs a `BUDGETS.md` reason row. Writes `.kassis/evidence/thin-addon-budgets.json`. Missing reasons are KADK-723. `certify` runs the same gate and records check id `adk.thin-addon-budgets`.                                                                                                                                                                                                                                                                                                                                      |
| `engineering`        | `--json`                                                      | Scans addon source for outbound calls without timeouts (KADK-724), `findMany` without `take`/`skip` (KADK-725), UI chrome outside i18n or `i18next` imports (KADK-726), non-idempotent job/event handlers (KADK-727), and module-level `let`/`var` state (KADK-728). Writes `.kassis/evidence/engineering-practice.json`. `certify` runs the same gate and records the five check ids.                                                                                                                                                                                                                                                                         |
| `scaffold`           | `--kind` `--id` `--name` `--dir`                              | `--kind=addon` is init. The other kinds add a route, capability, event, job, migration, UI slot, UI page, or MCP tool in the current addon. `scaffold route` writes `src/server/routes/<name>.ts`, adds the permission, depends on `express`, and calls the mount helper from `initialize`. `scaffold job` writes `src/server/jobs/<name>.ts` and registers the handler from `initialize`. `scaffold event` writes `src/server/events/<name>.ts`, `schemas/<name>.schema.json` with required fields, and `events.publishes` in the manifest. `scaffold migration` writes `migrations/<nnnn>_<name>.{up,down}.sql`, sets `data.schema`, adds a qualified row to `database.ownedTables`. Install and update apply those scripts for a tier 2 package. `scaffold ui-slot` and `scaffold ui-page` add `ui.contributions.nav`, write `src/ui/pages/<name>.tsx` using `@kassis/host-sdk`, `src/ui/locales/en.json` and `fr.json`, wire the page into `src/ui/index.ts`, and add `test/ui/<name>Page.render.test.ts` (requires rung 2 or 3). `scaffold mcp-tool` declares `contributions.mcp` with `dist/mcp/contribution.js`, writes `src/mcp/tools/<name>.ts` via `@kassis/mcp-contract`, wires `src/mcp/contribution.ts`, and adds `test/mcp/<name>.mcp.test.ts`. `scaffold capability` adds `<id>.<name>` version `1.0.0` to `provides` for tier 1 and tier 2. |
| `pack`               | `--out=<dir>` `--json`                                        | Writes an evidence pack after certify would pass: attestation, lock, certify result, `index.json` and `README.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `sbom`               | `--json`                                                      | Writes `sbom.json` for the libraries this addon ships. Versions come from `package-lock.json`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `package`            | `--out=<path>` `--json`                                       | Writes `<id>-<version>.addon` beside the addon folder (or at `--out`). The file is a zip of the signed `manifest.json`, the files in the content-hash scope, `frontend/dist/` when that folder exists, the certify evidence pack (`checks.json`, `attestation.json`, and `agent-profile.lock.json`), and `sbom.json`. It writes `sbom.json` when that file is missing or older than the server build. It prints the file path and the sha256 of the zip. It refuses a manifest with no signature or no `contentHash`, and a folder whose certify checks did not all exit 0. It does not sign and it does not call the network. Sign again after `sbom.json` changes. |
| `deploy`             | `--instance=<url>` `[file.addon]` `--json`                    | Uploads the `.addon` to `POST /api/v1/addon-security/deploy` and prints the approval request id. `--instance <url>` and `--instance=<url>` both work. The token is `KASSIS_ADK_TOKEN`. The optional field `archiveSha256` is the sha256 of the uploaded bytes. The same command works from a jump host that only has the `.addon` file.                                                                                                                                                                                                                                                                                                                              |
| `status`             | `--instance=<url>` `--json`                                   | Prints the installed version and pending staged versions from `GET /api/v1/platform/addons/installations`. The token is `KASSIS_ADK_TOKEN`. Each row is the addon id, active version, publisher, and pending versions.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `sign`               | `--key=<path>` `--json`                                       | Signs this addon. With `--key`, writes `contentHash` and `signing.keyId`, then the signature. Refuses a key file inside the addon folder. Inside the repo, without `--key`, uses the repo signer for the manifest id and does not add `signing`. Outside the repo, `--key` is required.                                                                                                                                                                                                                                                                                                                                                                              |
| `keys generate`      | `--publisher=<id>` `--json`                                   | Writes an Ed25519 private key to `~/.kassis/keys/<fingerprint>.key` (mode 0600; on Windows, only the current user). Prints the fingerprint and the public key. The private key is not written into the addon folder.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `keys export-public` | `--key=<path>` `--out=<path>` `--json`                        | Writes the SPKI DER hex of that private key.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `keys register`      | `--instance=<url>` `--publisher=<id>` `--key=<path>` `--json` | POSTs the public key to `/api/v1/platform/addon-publishers/<id>/keys`. Token: `KASSIS_ADK_TOKEN`. The instance still has to approve the key.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `certify`            | `--json`                                                      | Runs check, conformance, build, test, requirements tracing, requirement mapping, soft budgets, and engineering practice; writes `.kassis/evidence/checks.json` (machine check ids `adk.requirements-traced`, `adk.requirement-plan-mapped`, `adk.attest-pinned-profile`, `adk.thin-addon-budgets`, and the five group E check ids); then checks the attestation. KADK-714 blocks a blank outcome. KADK-715 warns when machine evidence is typed in. Untraced Must ids also emit KADK-718/719. A missing or invalid plan emits KADK-720/721/722. Budgets emit KADK-723; engineering emits KADK-724–728. The mandatory record contract emits KADK-729–732 and records check id `adk.mandatory-contract-intact`. A fresh `scaffold record-type` fails that check because `canAccess` and `onDelete` only throw. The same run applies the group A reuse checks (KADK-221, KADK-310, KADK-311, KADK-312). `--json` prints `{ "ok", "issues", "data" }` and still exits 1 when `ok` is false. |
| `attest`             | `--json`                                                      | Writes `.kassis/attestation.json` from the lock when it is missing, then prints its path. It does not post to the registry. `certify` posts when the instance env vars are set.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `explain`            | `<code>` `--json`                                             | Prints the meaning of a KADK code.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `sync`               | `--profile=<id>` `--instance=<url>` `--from=<file>` `--json`  | Verifies the signed profile, reads `--from`, or downloads `GET /api/v1/agent-registry/profiles/published/<id>`, then writes the lock and the rule files.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `rules`              | `--json`                                                      | Rewrites `AGENTS.md` and the rule files from the lock. Fails if you have not run `sync`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

`sync --instance` reads the published profile route. The id is a slug such as `addon-coding-agent`, not a database number. The response body is `{ success, data }`. The CLI uses `data`.

Example:

```bash
node tools/adk/kassis-addon.mjs init --id=sample-tprm-check --publisher=kassis --dir=../sample-tprm-check
node tools/adk/kassis-addon.mjs certify --json
```
