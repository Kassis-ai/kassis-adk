# @kassis/addon-sdk

The public contract between a Kassis addon and the host:

- `AddonContext` v1: the only object an addon receives, bound to its id (types only; the host implements it from Phase 3b).
- Manifest v2: a JSON Schema (`schema/addon-manifest.v2.schema.json`), the `AddonManifestV2` type, and `validateManifestV2()`.
- `KADK` error codes: a data catalog (`codes/kadk-codes.json`) with a typed accessor. Every code is documented in [docs/developer/reference/adk-error-codes.md](../../docs/developer/reference/adk-error-codes.md).
- Tier capability matrix (`tier-matrix.json`): each `ctx` facade method with `tier1`, `tier2`, and manifest or principal permission gates. `npm run ci:adk:tier-matrix` keeps tier 2 rows aligned with the host allow-list.

Tier 1 (first-party, in process) and tier 2 (client code, own process) addons compile against the same package. An addon does not know which tier it runs in.

## Rules

**Self-contained.** The package imports only its own files and the npm packages declared in its `package.json` (`ajv`). No `@/`, no `server/`, no relative path out of the package, no Node built-ins, and no other `@kassis/*` package. `npm run ci:packages:addon-sdk-boundary` enforces this in CI with no baseline. A `@kassis/*` package can be allowed only after checking that it is self-contained too, by adding it to `SELF_CONTAINED_KASSIS_PACKAGES` in `tools/ci/check-addon-sdk-boundary.mjs`. Today the list is empty.

**Versioning.** The major version equals the host API major (`HOST_API_VERSION` in `src/host/version.ts`, today `1.0.0`), so the package is `1.0.0`. A breaking change to the contract needs a new host API major. New optional fields, facades and codes are minor releases; a deprecated API keeps working for at least one minor release. The package publishes to GitHub Packages (`publishConfig.registry` is `https://npm.pkg.github.com`). The published entry is JavaScript in `dist`. Inside this repository the `development` export condition still resolves `src`.

**Stable codes.** A published `KADK` code keeps its number, category and meaning. A retired code is marked retired in the catalog and the docs page; its number is never reused. New codes take the next free number in their range: 1xx manifest, 2xx boundaries, 3xx data, 4xx events, 5xx UI, 6xx security, 7xx attestation.

**One definition per shape.** Where the host has the same registration shape, the host type is the SDK type plus `addonName`, through a type-only import (for example `CapabilityRegistrationInput = CapabilityProvision & { addonName: string }`). Contribution types marked "host-specific" differ from the host's because the host uses Prisma or untyped values; the host adapts them in 3b.

## Using the context

```ts
import type { AddonContext, AddonManifestV2, DeclareAddon } from '@kassis/addon-sdk';

export const manifest = {
  manifestVersion: 2,
  id: 'sample-tprm-check' /* … */,
} as const satisfies AddonManifestV2;

type Declarations = DeclareAddon<
  typeof manifest,
  {
    publishes: { 'sample-tprm-check.assessment.completed': { partyId: string; score: number } };
    subscribes: { 'party.updated': { partyId: string } };
  }
>;

export async function initialize(ctx: AddonContext<Declarations>): Promise<void> {
  ctx.events.subscribe('party.updated', async (event) => {
    await ctx.audit.record(event.principal, 'sample-tprm-check.assessment.run', {
      subject: { type: 'party', id: event.payload.partyId },
    });
  });
}
```

With declarations, an undeclared event, audit action, job type, prompt key, secret key, route permission or capability does not compile. Without them every name is a `string`; the host checks the manifest at runtime either way. Declare payload types with `type`, not `interface`.

Contract rules built into the types:

- No method takes an addon name. The host binds identity.
- Every registration returns a `Disposable`. Registrations complete before the addon is marked ready, so a failed registration fails `initialize()`.
- Every operation on core data takes an `AddonPrincipal`. Only the host issues principals: `ctx.routes.principalOf(request)` in a route, `event.principal` and `job.principal` (the addon's service principal) in handlers. Facades check that principal's permissions and tenant.
- Every facade operation is async, so tier 2 can implement it over RPC. `ctx.capabilities.consume` returns `C | null`, and every caller handles `null`.
- `ctx.llm.invoke` takes a declared prompt key and variables. Model, provider, temperature, token limits and timeouts come from AI Settings and the prompt template; the host tags usage with the addon id.
- `ctx.audit.record` has no best-effort variant. It rejects when the record cannot be written.

## Manifest v2

Fields: `manifestVersion` (2), `id`, `name`, `version`, `publisher`, `tier`, `hostApi` (all required); `entrypoints.main`, `signature`, `contentHash`, `permissions[]`, `requiredPermissions`, `requires[]` and `optional[]` (capability + semver range), `provides[]` (capability + version), `events.publishes[]` (name + schema file), `events.subscribes`, `audit.actions`, `egress.hosts`, `jobs.types`, `prompts.keys`, `secrets.keys`, `config.schema`, `data.schema`, `database.ownedTables`, `database.readAccess`, `legacyTables[]`, `contributions.mcp`, `resourceTypes[]`, `ui` (entry file, runtime load, contributions, `slots`), `metadata` (informational only).

`validateManifestV2(manifest, options?)` returns `{ ok, issues }`; each issue has `code`, `path`, `message`, `fix` and `docs`. It runs the schema with Ajv, then the rules a schema cannot express:

- Permissions, job types, prompt keys, published events and audit actions start with `<id>.` or the id with underscores; secret keys start with `<id>:`.
- No duplicate entries; a capability is not both required and optional; every `requiredPermissions` entry is declared.
- Tier 2 cannot declare `legacyTables` or `database.readAccess`, and its owned tables are qualified with `data.schema`, which must be `addon_<id with underscores>`.
- Tier 1 `legacyTables` name owned tables; a rename lands in the addon prefix.
- Package paths stay inside the package; event schemas are `.schema.json` files; runtime-loaded UI has an entry file.
- With `options.reservedNamespaces` (the host's core namespaces), the id must not be one of them.

The function is pure: no file system, network or environment access.
